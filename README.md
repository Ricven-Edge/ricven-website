## Future website upgrades

The current website is a lightweight static HTML, CSS, and JavaScript-free site hosted with GitHub Pages. This keeps it simple to maintain and publish. It can be upgraded gradually as the company and products grow.

A sensible upgrade roadmap is:

1. **Brand and visual assets** — add approved company identity assets, app icons, real product screenshots, and refined visual details.
2. **Responsive experience** — continue checking navigation, layouts, typography, and accessibility across mobile, tablet, and desktop screens.
3. **Product content** — expand each product page with verified features, screenshots, FAQs, release notes, support information, and real download links when available.
4. **Shared site components** — reduce repeated page styling and markup with a maintainable shared structure as the number of pages grows.
5. **Performance and accessibility** — review page weight, loading behaviour, semantic structure, keyboard navigation, contrast, and metadata.
6. **Search and discoverability** — add appropriate social sharing metadata, sitemap, robots instructions, and structured metadata where useful.
7. **Optional dynamic capabilities** — consider a framework, content management workflow, or backend only when a real requirement justifies the added complexity.

These are future opportunities, not claims that the current website already has these capabilities. Upgrade decisions should be made incrementally, with each change reviewed and tested before publishing.

## Publishing and workflow

GitHub Pages publishes the site from the `main` branch and the repository root (`/(root)`). Develop and review changes on a working branch before merging into `main`. Do not merge or publish a change until it has been reviewed and approved.

Screenshot areas and download sections remain placeholders until approved product imagery and verified release links are available. Do not publish placeholder downloads.
